# G5 code review (a separate sub-agent; never whoever wrote the code)

Generic items. Product items are in the gate-extension file named in `specflow.md`. Scope = the prep commit to HEAD. Basis = this dispatch's spec, contracts, implementer rules and deferred list, **plus rules in other specs that name this component** (found with the impact search in `specflow.md`).

| Item | Check | Passes when |
|---|---|---|
| G5-1 | Tests test the behavior | No empty assertions, commented-out cases, or thresholds loosened to go green |
| G5-2 | The test list is complete | Every row of spec 5.1 has a matching test |
| G5-3 | Prohibitions not bypassed | The diff does not touch build settings, frozen contracts or other components |
| G5-4 | Architecture boundaries hold | The pure-logic layer has no framework or hardware headers; the adapter layer makes no business decisions |
| G5-5 | Error paths handled | More than the happy path works |
| G5-6 | Style, rule by rule | One row per implementer-rules style rule tagged [G5] (Conforms / Violates / N/A); read every touched file in full, not just the added lines |
| G5-7 | Reasons for letting something pass cite a source | A pass justified by "another component handles it" or "another layer has a timeout" cites that component's spec or code `file:line`; with none found, it cannot pass on that ground |
| G5-8 | No false claims | "Verified on device" backed only by host-side test evidence is sent back |
| G5-9 | Deferrals recorded | Every finding judged as not fixing, fix next time, worked around, or unchanged by agreement goes on the deferred list; items on the list marked "review at next G5" are reviewed this time |
| G5-10 | Check table | One row per in-scope rule; row count = number of in-scope rules; passes only with no Violates |

## Check-table format (separate from the G5-6 style table)

| Rule ID | Code location `file:line` | Verification | Verdict | Notes |
|---|---|---|---|---|

- Rule ID: `<spec ID> <section>#<n>`.
- Verification: the test named in the Verify cell exists and fails when the rule is broken; for `untested: <reason>`, say whether the reason still holds. For a rule tied to a couplings row, write that row's "How kept consistent".
- Verdict: Conforms / Violates / N/A / Cannot judge from diff. "Cannot judge from diff" goes back to the main session to check itself.
